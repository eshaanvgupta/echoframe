## Delivered behavior

- **Exact intended-payment attribution.** Execution, ERC-20 logs, intended purchase, authority, delivery observation and reproduced outcomes are separate. Positive live attribution requires trusted chain, transaction context, token, sender, recipient, exact atomic amount and explicitly selected log, plus configured token semantics. A sole log is never automatically selected. Missing expectations, pending/removed/orphaned/invalid receipts, token uncertainty and RPC contradiction remain unresolved. Settlement never proves delivery.
- **Conservative independent verification.** Real imported financial statements remain recorded claims; they cannot supply their own trusted purchase context. SIMULATED financial states remain explicitly virtual. Public-minimal event names cannot establish delivery after their payloads are withheld. Evidence/proof formats remain 1.0.0; expanded verifier reports and diagnoses are 1.1.0.
- **Durable drop-in instrumentation.** `PaymentRecorder.express()` and `.hono()` observe real framework lifecycles using current official x402/MPP codecs. Opaque request correlation, selected quote commitments, safe authorization fingerprints, protocol response/transaction references, local attempt history, read-only reconciliation, bounded merchant response commitments, explicit JSON projection policies, intentional complete export and restart recovery work through the installed SDK. MPP supports its advertised alternate credential header alongside ordinary Bearer authentication, rejects ambiguous payment headers and never retains either credential. Bundle recovery summaries are synchronized with the durable journal.
- **Privacy defaults.** No raw payment headers, signatures, credentials, cookies, request bodies or wallet keys enter recorder storage. Default response capture retains metadata and commitments. Optional JSON allowlists retain only deliberate projections with sensitive-name/known-secret redaction; arbitrary personal-data detection is not guaranteed. RPC endpoint credential paths/queries, raw errors and unknown receipt extensions are withheld.
- **Trace-aware diagnosis.** Seventeen typed classifications cover supported drift, missing expectations, ambiguous/multiple transfers, repeated identities, response/delivery loss, hash/schema/bounds failure, insufficient evaluator/source evidence, RPC contradiction, recovery and unsupported profiles. Findings cite events/hashes, missing evidence, safe actions, relevant simulation, observed-condition severity and reproducibility. Explorer, CLI and MCP use the same engine. Complete-evidence trace regressions are explicit and runnable; imported scripts are never executed.
- **Developer and product completion.** Executable installed-package, Express, Hono, CLI and MCP examples; metadata defaults, policy opt-in, persistence/recovery/export and genuine merchant opt-in are documented. Existing screens and identity are preserved, expanded evidence axes and diagnoses are functional, stale studio proofs clear on edits, narrow-screen status labels stay readable, and IndexedDB/offline workflows remain operational.
- **Distribution.** Nine versioned ESM/declaration tarballs, static Cloudflare Pages directory/ZIP, checksum manifest and reproduction scripts are prepared. No registry or website publication is claimed. GitHub CI builds the same versioned assets after its checks.
