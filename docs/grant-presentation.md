# ECHOFRAME

**The Verification Layer for Autonomous Commerce**

**Money moved. Did the work happen?**

Prezenti Frontier category: **AI & Agent Economy Infrastructure — Verification and Trust Infrastructure**.

## 1 — The operational problem

An agent accepts a quote, authorizes a payment and receives an uncertain response. A successful Transfer cannot establish that the quoted recipient was paid for this request, that usable work arrived, or that repeating the request is safe. Developers need a portable record that separates these questions and reproduces failures without more economic activity.

## 2 — Implemented infrastructure

Nine independently installable packages provide strict Celo attribution, Express/Hono recording, deterministic outcome proofs, durable attempts, CLI/MCP inspection and reusable verdict components. The static web application connects trace inspection, 16 failure simulations, visual policies, journal recovery and evidence exports. No mandatory paid infrastructure or AI service determines the verdict.

## 3 — One evidence path

Request → pinned quote → safe authorization metadata → protocol observation → selected onchain Transfer → retained result commitment → independently reproduced policy → diagnostic finding → executable regression. Each statement retains its provenance and missing evidence. Financial, delivery and authority verdicts remain separate.

## 4 — Demonstrated genuine integration

One owner-approved, self-operated Celo Sepolia purchase moved 0.01 test-USDC using MetaMask and the official hosted x402 facilitator. Exact expectations matched Transfer log 1, HTTP 200 content matched its commitment, and the outcome proof reproduced independently. The original rejected header and separately sourced read-only recovery remain visible. Complete redacted evidence was published with explicit owner consent. This is testnet integration evidence, not mainnet traction or independent adoption.

## 5 — Engineering reviewers can reproduce

The release includes a clean-checkout CI workflow, nine packed SDKs, an external installed-package consumer, generated regressions, four responsive widths, offline recovery, automated accessibility, performance and dependency/license checks. Exact counts come from release-verification.json. Public release archives have SHA-256 checksums. The demonstration and evidence can be verified without wallet access.

## 6 — Celo contribution and differentiation

ECHOFRAME contributes a reusable evidence-to-regression workflow for Celo x402/MPP builders. It checks runtime chain identity, exact atomic expectations and explicit Transfer selection instead of treating a dashboard receipt as purchase proof. Payment middleware authorizes/settles; ECHOFRAME explains what was observed and what can be reproduced. Seller reputation estimates counterparties; ECHOFRAME verifies the particular declared result. These are complementary tools, not claims that existing receipts, controls or reputation systems are new inventions.

## 7 — Adoption strategy

Start with ten consenting Celo merchant and agent developers through documented pairing sessions. Make each activation an independently installed recorder, exported trace and verifier run. Recruit framework maintainers through executable bug reproductions and protocol compatibility fixes. Expand toward 30 then 100 activations only as independent usage is observed; publish opt-in feedback and contributed scenarios. No tracking pixel, manufactured buyer, wash payment or download-count proxy is used as adoption.

## 8 — Four-month request

Proposed request: **up to 15,000 USDm**, subject to current program terms and eligibility confirmation. Month 1: integration documentation and ten-builder activation effort. Month 2: supported-profile interoperability and independent bug reproductions. Month 3: security hardening, mobile/accessibility review and a separately authorized consenting mainnet integration if available. Month 4: repeatable public evidence, community cases and maintenance handoff. Targets are future milestones; none is reported as achieved.

## 9 — Scope, eligibility and maintenance

The official Season 3 criteria require a working Celo mainnet deployment and associated verifiable activity. The public static application, read-only mainnet inspection and Sepolia self-test do not establish those requirements. Independent adoption, mainnet integration, meaningful Self Agent ID use/commitment and applicant/KYC/KarmaGAP information remain external prerequisites. ERC-8004 has an infrastructure exception requiring program confirmation. No grant application has been submitted automatically.

Maintain pinned protocol profiles, monthly advisory reviews, full release checks and backward-compatible proof semantics. Triage reports without credentials, require consent for contributed real traces, and preserve conservative UNKNOWN outcomes. No external audit, consensus proof, universal security guarantee or future funding is claimed.
